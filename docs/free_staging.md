# Бесплатный тестовый стенд MTaxi

Конфигурация: `render.yaml` — Docker backend на бесплатном Render Web Service,
бесплатная PostgreSQL и бесплатный Static Site для Flutter web.
Админка открывается на том же Static Site по `/admin` и требует роль admin.
Планы платного compute и persistent disk не используются.

## Текущий статус

Конфигурация проверена по официальной JSON Schema Render. Публичное
развёртывание ещё не выполнено: у среды нет авторизации Render.
GitHub-репозиторий доступен, Firebase FCM credentials уже предоставлены.
Не выдавайте предполагаемые `*.onrender.com` адреса за созданные приложения.

Для автоматического продолжения добавьте `RENDER_API_KEY` в защищённые
переменные облачной среды. Создание ключа: Dashboard Render → Account Settings
→ API Keys. Не вставляйте ключ в чат, Git или APK.
Ключ не создаёт сам аккаунт: если его нет, требуется регистрация владельца.

## Порядок развёртывания

1. Опубликовать проверенные изменения в отдельной ветке GitHub. Локальные
   незакоммиченные изменения не попадают на Render автоматически.
2. Создать Blueprint из этой ветки с `render.yaml`. Все instance plans — `free`.
3. Передать backend `FIREBASE_SERVICE_ACCOUNT_JSON` через Render secret env,
   указать реальный `MTAXI_ADMIN_PHONE`. Пароль первого администратора и секреты
   сгенерирует Render; не публиковать их в логах или исходниках.
4. `start_render_staging.js` получает фактический `RENDER_EXTERNAL_URL`, применяет
   схему PostgreSQL, выполняет production preflight и создаёт администратора
   только при его отсутствии. Перезапуски не возвращают старый пароль.
5. После назначения Static Site реального адреса установить backend
   `MTAXI_CORS_ORIGINS` в этот точный HTTPS origin и перезапустить backend.
   Начальное значение разрешает только origin самого backend, без wildcard.
6. Static Site получает hostname API из Render. Скрипт сборки использует
   Flutter 3.41.2 с проверкой commit, frozen pub lockfile и remote URL guard.
7. Проверить внешние `/readyz`, регистрацию по паролю, вход пассажира и админа,
   новый заказ, комиссию/бонусы, ручную Kaspi-заявку и переключатель межгорода.
8. С фактическим HTTPS URL API собрать тестовый APK:

   ```bash
   bash scripts/build_test_apk.sh https://ACTUAL-API-HOST
   ```

   Скрипт сначала проверяет настоящий `/readyz` и PostgreSQL, затем создаёт
   `output/mtaxi-staging.apk` и SHA-256. Это тестовая debug-подпись, не релиз для магазина. Проверить APK на устройстве
   и дать ссылку на фактически созданный файл вместе с SHA-256. Не раздавать
   сборку с localhost, LAN или выдуманным адресом как рабочую удалённую версию.

## Ограничения бесплатного стенда

- Web Service засыпает после 15 минут без входящих запросов; пробуждение может
  занимать около минуты. Бесплатный лимит — 750 instance-hours на workspace
  в месяц. Не имитировать трафик, чтобы обходить сон сервиса.
- Бесплатная Render PostgreSQL истекает через 30 дней. До срока экспортировать
  данные существующим backup-инструментом, затем перенести на другой стенд или
  боевой PostgreSQL. Бесплатные автоматические backups не обещаются.
- Диск Web Service эфемерный: загруженные фото теряются при redeploy/сон/рестарте.
  Стенд предназначен для синтетических данных и тестовых фото, не реальных
  документов водителей. Для постоянного хранения нужен отдельный object storage.
- Таймеры maintenance/push не работают, пока сервис спит. Это не круглосуточный
  production и не обещание постоянного времени отклика.
- Веб push ещё требует VAPID, iOS — APNs. Без VAPID веб-сборка поддерживает
  обычную админку и уведомления внутри приложения, без browser push.
- Межгород по умолчанию выключен. SMS отключены, оплата Kaspi подтверждается
  администратором вручную. Не проводить реальные деньги на тестовом стенде.
