# Аудит MTaxi — 23 октября 2026

**Статус: к публичному запуску не готов.** Исправлены воспроизведённые дефекты денег, доступа к документам и интерфейса. Проверка 1000 одновременных пользователей не пройдена: тест остановлен на 250 по порогу ошибок. Проверка Android/iOS на устройствах не выполнена. Это отчёт об исполненных сценариях, а не утверждение о проверке каждой кнопки.

## Версии и границы

Исходная опубликованная версия: `2492f638a10cff508b07d7e5f929097108117638`, Flutter `1.2.0+58`. Рабочая ветка: `codex/full-audit-20261023`, базовая ветка PR: `codex/free-staging-20261021`. Последний коммит приложения для повторной проверки: `5abe08f9bc5248c93c8f4bb3e795c323693c0821`. Последующие коммиты отчёта/инструментов не изменяют приложение. Версию `main` нельзя использовать как базовую для этого PR: там отсутствуют ранее внедрённые изменения.

Тестирование проведено локально, отдельно от рабочего сервера: PostgreSQL 16 в контейнере, четыре базы с префиксом `mtaxi_audit`, 1000 синтетических пользователей, отдельные каталоги документов и секреты стенда. Flutter 3.41.2, Node 24.19.0; production Docker использует Node 22. PostgreSQL ограничен 2 CPU/1 GiB, общий хост — 4 CPU/32 GiB, ресурсы делятся с браузером и сборками. Результат нагрузки нельзя переносить на VPS как измерение его точной ёмкости.

Геокодирование/маршрутизация заменены строгими тестовыми адаптерами. SMS/FCM выключены, Kaspi только ручной тестовый процесс, внешние платежи и массовые push не отправлялись. Проверка сайта — Chromium, мобильный viewport 390×844 и широкая админка 1440×844. GPS задавался браузером/тестом, физическое движение не проверялось. Нового деплоя и миграций production нет: последнее задание требует отдельного разрешения на них.

Второй заказ полностью бонусами 700: денежный баланс водителя вырос на 700, комиссия 70 списалась с бонусов, пассажиру начислено 14 cashback. Деньги пассажира при полной бонусной оплате не списались. Проверены записи в тестовой БД, а не только надписи.
- Регистрация водителя через форму: обязательные поля, неправильный госномер, дата рождения/город, обязательность двух фотографий, реальный file chooser и перезагрузка. Администратор просмотрел закрытые файлы и подтвердил; приветственные 1000 начислены один раз, повторное подтверждение не удвоило бонус.
- Через браузер также выполнена заявка пассажира на пополнение 500: до подтверждения баланс не изменился, после внутренней отметки выставленного счёта также не изменился, после административного подтверждения вырос ровно на 500; пассажир увидел успешное пополнение. Реальный счёт/банковский перевод не совершались.
- Администратор нашёл пользователя за пределами первых 500, изменил имя без изменения телефона/балансов. Редактор экономики сохранил комиссию 10%, cashback 2%, акцию 10 заказов→1000, межгород выключен.

## Нагрузка и обновления

Модель: 600 пассажиров / 390 водителей / 10 администраторов, отдельные JWT-сессии всех 1000 аккаунтов. В финальном запуске опрос состояния 2 с, GPS 3 с; условные выдержки assigned 30 с, arrived 15 с, started 90 с. Частота и длительность — явно заданная синтетическая модель, не статистика реального посёлка. Опрос состояния через getSessionBootstrap приближает клиентское поведение, но не является точным воспроизведением всех вызовов getOrderDetails. Доставка обновлений — HTTP polling, WebSocket в проверяемой реализации не используется.

План: smoke 5×120 с; 50/100/250/500/1000 по 180 с; 1000×900 с; 100→1000 за 10 с и hold 120 с; восстановление. Сценарии остановки — финансовая целостность или >5% неожиданных ошибок за скользящую минуту. Первые неудачные прогоны не удалены.

| Финальный запуск `load-validation.json` | Факт |
|---|---|
| Smoke 5 | 120 с, 484 запроса, 0 неожиданных ошибок |
| 50 | 180 с, 6780 запросов, 0 ошибок, 26 завершённых поездок |
| 100 | 180 с, 6190 запросов, 0 ошибок, 49 завершённых поездок |

| Восстановление | 121 с, 275 запросов, 0 неожиданных ошибок |
| 500, 1000, hold 15 минут, spike | **Не выполнялись после аварийной остановки** |

Итоговые p95 по всем выполненным этапам: bootstrap 2844 мс, создание заказа 12006 мс (таймауты), лента водителя 12001 мс, принятие 5017 мс. Отдельная оценка доставки изменённого состояния другому участнику: 204 наблюдения, p95 6879 мс, p99 7733 мс; промежуточные состояния, перезаписанные до наблюдения, в оценку не попадают. Возраст GPS: 3093 наблюдения, p95 6175 мс, p99 12658 мс. Это синтетические foreground-координаты; фон/потеря связи/нативное энергосбережение не измерены.

На мониторируемых снимках БД отрицательные балансы, повторные назначения и дубли типов денежных проводок — 0; deadlocks 0. Это наблюдение за выполненной нагрузкой, не математическое доказательство отсутствия любых гонок. В окне финального теста максимум процесса backend: CPU 113,2% одного ядра, RSS 413,8 MiB, event-loop p95 в худшем пятисекундном интервале 52,6 мс; PostgreSQL — до 12 соединений и 9 ожидающих, память до 412,5 MiB из 1 GiB; OOM 0. CPU/RSS/event-loop, блокировки/соединения PostgreSQL, память контейнера, события OOM и квоты хоста сохранены в JSONL и сводке ресурсов. Запуск с более редким GPS 5 с также дошёл до 250 и был остановлен по ошибкам; его нельзя выдавать за подтверждение 1000.

Узкое место остаётся: изменяющие запросы загружают большой snapshot и последовательно проходят общую advisory-блокировку. Дельта-запись и чтение без глобальной write-блокировки заметно улучшили диагностический тест 50 сессий (230 ошибок из 252 до, 0 из 1156 после), но не решили масштабирование записи. Нужны операции по конкретным сущностям в SQL, атомарные переходы/резервы, индексы и повтор полной лестницы на выделенном стенде. Нельзя снимать финансовые блокировки без эквивалентных ограничений целостности.

## APK и iOS

Создан отдельный workflow `audit-native.yml`: собирает **изолированный** профильный APK, читает существующий ключ, сравнивает сертификат с фактически опубликованным APK и сохраняет приватный GitHub artifact. Не деплоит на VPS и не меняет ключ. APK направлен на `http://127.0.0.1:18084`: для устройства требуется adb reverse и локальный стенд; это не ссылка на новое боевое приложение.

Пакет `com.milanium.mtaxi`, версия `1.2.0`, код `58`. Сертификат опубликованного текущего APK: `53ce69859ae2fafd3064d3df77d0527c6d4d5bee1f739658220bc9b245ea47bd`. Сборка кандидата сравнивает этот сертификат, SHA256 бинарника и результат локальной проверки сохраняются в `apk-final/`. Финальная сборка [39952298369](https://github.com/milaniumkz/mtaxi/actions/runs/39952298369) успешна, APK скачан и проверен локальным apksigner; SHA256 `71ee400f9605f48dcbe22056141305a970f07e6a80fb8d51ce6480632489d2dc`. Равенство сертификата — только статическая проверка, не успешная установка поверх существующей версии.

У старых конкретных локальных APK обнаружен другой сертификат (`3b3a30d9880a7a340d754c13ce2118ef8224dea7d2dbe2eed7b767bf2ba0e0f7`). Преемственность с такими установленными приложениями не подтверждена; нужны исходный ключ и тест на устройстве. Удалять приложение для сокрытия проблемы не предлагается. Новый ключ не создавался.
