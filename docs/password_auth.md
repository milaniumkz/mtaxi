# Вход по номеру телефона и паролю

SMS не используются: пользователь выбирает «Создать аккаунт», указывает номер
в формате +7, пароль от 8 до 128 символов и повторяет пароль. После этого выбирает
роль и заполняет профиль. Пароль повторно в профиле не запрашивается.
Водители по-прежнему проходят одобрение администратора.

Номер — логин, а не подтверждённый контакт: новая регистрация сохраняет
`phoneVerified=false`. Без SMS/звонка нельзя доказать владение SIM-картой.
Заявки водителей следует проверять до подтверждения; изменение номера и спор
о принадлежности аккаунта решает администратор после проверки личности.

Существующие пароли продолжают работать, включая старые короткие пароли.
Повторная регистрация занятого номера не меняет пароль или баланс.
Старые аккаунты без пароля требуют ручного восстановления администратором.

## Восстановление без затрат на сообщения

Пользователь нажимает «Забыли пароль?» и получает инструкцию обратиться
к администратору. Автоматического восстановления по одному номеру нет.
Администратор после проверки личности открывает «Пользователи» →
«Редактировать» → «Новый пароль (от 8 символов)» и задаёт пароль.
Пустое поле оставляет пароль прежним. Пароль нужно передать лично либо по
заранее проверенному каналу; не доверять обращению только по введённому номеру.
После сброса все ранее выпущенные сеансы аккаунта недействительны.

Пароли хранятся как salted scrypt hashes и не возвращаются клиенту.
Сброс не записывает пароль или hash в журнал аудита. Номер телефона сам по себе
не предоставляет прав администратора. Публичные auth-запросы ограничены по IP
и сочетанию IP/номер, в том числе при переборе разных номеров.

## Backend и развёртывание

- `registerWithPassword`: атомарно создаёт аккаунт и выдаёт сессию.
- `passwordLogin`: вход существующего пользователя.
- `requestSmsCode`, `verifySmsCode`, `createSmsSession`: всегда возвращают
  `SMS_AUTH_DISABLED`; обращения к SMS-провайдеру не выполняются.
- Старый маршрут `/smsVirefication` показывает обычный вход по паролю.
- `lookupUserByPhone` больше не раскрывает профиль без авторизации.
- `MTAXI_SMS_PROVIDER=disabled` — значение по умолчанию. SMS URL/token не нужны
  в production generator, env contract, VPS inputs или проверке handoff.

Нужен HTTPS для защиты пароля при передаче. Приватные сервисные ключи Firebase
относятся только к push и не заменяют парольную авторизацию.

Выпускать backend и клиент совместно: старая версия приложения с регистрацией
через SMS больше не сможет зарегистрироваться и должна обновиться.

## Межгород на время запуска

По умолчанию отключён. Администратор: «Настройки (runtime/комиссия/доставка)» →
«Редактировать» → переключатель «Межгород» → «Сохранить». Включение и повторное
отключение не требуют новой сборки. Клиенты обновляют настройку примерно
каждые 15 секунд; backend применяет изменение сразу. При отключении вкладка
скрывается и новые заказы запрещены также через API. Существующие заказы и
тарифы сохраняются.
