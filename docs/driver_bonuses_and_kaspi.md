# Посёлки, бонусы и ручное пополнение Kaspi

## Тарифы

Жетекши (Jetekshi), Железинка, Теренколь и Иртышск: такси 500 ₸ днём и ночью.
Другие посёлки сохранены. Тарифы доставки не меняются.
При первом запуске backend применяется одноразовая настройка этих посёлков;
последующие изменения тарифов в админке не перезаписываются при перезапуске.
Для уже работающего сервера можно выполнить из корня проекта:

```bash
node server/scripts/configure_launch_defaults.js
```

Для PostgreSQL задайте `MTAXI_STORE=postgres` и `DATABASE_URL` штатным способом.
Скрипт безопасно запускать повторно: после первого применения он сохраняет
изменения администратора.

## Бонусы водителя

- При первом подтверждении нового водителя — 1000 бонусных ₸, единоразово.
  Создание администратором уже подтверждённого водителя также даёт этот бонус.
  Повторное подтверждение не начисляет его заново. Ранее подтверждённым
  водителям бонус задним числом не начисляется.
- Суточная акция: 10 завершённых заказов → 1000 бонусных ₸, один раз за сутки.
  Отменённые заказы не учитываются. Пока акция отключена, заказы не учитываются.
- Сутки — с 00:00 до 00:00 по `Asia/Almaty` (UTC+5). В полночь обнуляются
  прогресс и право на суточную награду; заработанный бонусный баланс сохраняется.
- Комиссия списывается сначала с бонусного баланса, затем с денежного.
  При отмене пассажиром или администратором каждая часть возвращается на свой
  баланс. Бонусные средства нельзя вывести или превратить в денежный баланс.
- Главный экран водителя показывает бонусы, условия и прогресс акции;
  обновление — при открытии и каждые 30 секунд.

Админка → «Настройки (runtime/комиссия/доставка)» → меню ⋮ → «Редактировать»:
выключатель суточной акции, количество заказов и размер награды.
Изменение условий применяется к следующим завершениям заказов. Повторную
награду за уже выполненную акцию в те же сутки изменение условий не даёт.
Приветственный бонус 1000 ₸ не зависит от выключателя суточной акции.

## Ручное пополнение через Kaspi

1. Водитель открывает пополнение, указывает номер Kaspi и сумму.
2. В админке появляется счётчик ожидающих заявок; также создаётся уведомление
   в журнале push. Реальная push-доставка требует настроенного FCM и токенов.
3. Администратор открывает «Платежи», выставляет счёт самостоятельно в Kaspi
   на указанный номер и нажимает «Счёт выставлен».
4. После фактического получения оплаты администратор нажимает «Подтвердить
   оплату». Сумма зачисляется на денежный баланс. Повторное подтверждение,
   включая одновременные запросы, не зачисляет деньги повторно.
5. Неоплаченную заявку можно отклонить. Отклонённая заявка не подтверждается.

Приложение не выставляет счета в Kaspi автоматически и не проверяет банковскую
оплату. Решение о зачислении принимает администратор после проверки в Kaspi.
API-ключи платёжного провайдера для этого сценария не нужны.
При необходимости режим можно задать для API по умолчанию:
`MTAXI_PAYMENT_PROVIDER=kaspi_manual`. Клиент запрашивает этот режим явно.

## Проверки

```bash
npm test --prefix server
flutter test --no-pub
flutter analyze --no-pub
flutter build web --no-pub --no-web-resources-cdn --dart-define=MTAXI_BACKEND_URL=http://127.0.0.1:8081
```

Последняя команда создаёт локальную проверочную сборку. Для публикации нужна
сборка с реальным HTTPS URL backend и проверка реальных SMS/FCM, HTTPS,
восстановления данных и работы приложения на устройствах.

`--no-web-resources-cdn` включает ресурсы движка Flutter в сборку, чтобы её
запуск не зависел от загрузки CanvasKit с CDN.
