# MTaxi — продолжение исправлений и нагрузки, 23 октября 2026

Продолжение [первого аудита](full_audit_2026-10-23.md). В рабочий VPS изменения не выкладывались. Все базы, аккаунты, деньги и координаты синтетические; карты/маршруты через тестовые адаптеры, SMS/FCM отключены, реальный банк не используется.

## Исправления

1. Опрос сессии, маршрута, истории и водительской ленты выбирает нужные записи, а не все таблицы базы. Поиск встречных предложений загружает участников конкретного заказа. Количество завершённых поездок водителя сохранено: история этого водителя учитывается отдельно.
2. GPS и финансовые операции берут разделяемую advisory-блокировку для совместимости с прежними операциями полного snapshot. Затем блокируют конкретный заказ и строки его участников. Прежние административные/полные операции по-прежнему берут исключительную advisory-блокировку. Независимые поездки выполняются параллельно; один заказ или баланс — последовательно.
3. Порядок блокировок: заказ, затем участники по отсортированным ID. Для пользователей используется `FOR NO KEY UPDATE`, совместимый с FK-проверками уведомлений другим водителям. Неизменённый уникальный телефон исключён из UPDATE, чтобы не повышать блокировку. GPS перепроверяет activeDriverOrderId после захвата пользователя и повторяет транзакцию, если назначение успело измениться. После четырёх смен указателя используется безопасный путь через исключительную блокировку.
4. Чтение/авторизация имеют отдельный пул соединений: очередь записей не забирает все соединения у карты и сессии. У частичных транзакций запрещено удаление строк. GPS может менять только координаты/предпочтения и разрешённые поля активной поездки, без изменения денег. Финансовая транзакция может изменять только заблокированных участников и свой заказ, а проводки/уведомления — только добавлять. Выборки финансовых операций ограничены текущими участниками, их активными ссылками и нужной историей водителя; полные профили читаются только для заблокированных участников. Для прежнего охвата уведомлений отдельно читаются только ID и признаки роли владельцев токенов; чужие полные профили не загружаются и не перезаписываются.
5. Добавлены индексы `ledger(order_id)`, `notifications((data->>'orderId'))`, `notification_deliveries(notification_id)`. Без них узкие запросы всё равно сканировали бы растущую историю. Миграция `2026-10-23-scoped-load-indexes` применена **только на тестовых базах**.
6. Административные списки заказов и статистика денег больше не загружают несвязанные таблицы.

Протокол/экономика не менялись. Flutter-код и APK прежние; исправлен backend. Не создавались новые ключи подписи. Результаты Android/iOS предыдущего аудита остаются ограниченными отсутствием устройств/Xcode.
